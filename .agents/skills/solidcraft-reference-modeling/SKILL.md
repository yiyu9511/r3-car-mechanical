# 参考件驱动的 SolidCraft 建模

目标是让用户的功能要求在模型里成立，并让用户能看见、修改和验证结果。
本 skill 记录方法，不把某一版托架的尺寸或形状变成后续模型的默认答案。

## 先确定这次到底做什么

先读仓库 `AGENTS.md`、`README.md`、`docs/当前设计.md`，再找用户指定的组件源文件。
遇到本次电池托架，另读 `cad_solidcraft/电池托架需求存档.md`。

- 最新用户指令优先。旧文档里的“已确认”不能抵消用户刚刚给出的修改。
- 分清**用户要求、源实体测量、设计假设、旧版实现**。不要把旧模型里存在的东西自动理解为要求。
- 第一个关键决定是连接方式：打印自攻柱、铜柱、螺母夹持是不同结构。先把五金规格和装配顺序写清，再画固定部位。
- 用一小段话说明保留什么、修改什么、哪些数字尚为假设。只有影响几何且无法从已有证据确定的问题才需要询问；已授权的局部修改继续完成。
- 用户在过程中说“左右”“这里”“加厚”等，先读取当前窗口或最新截图，按他正在看的方向解释，避免套用模型坐标猜位置。

## 以原始实体为尺寸基准

用源文件本身测量单位、实体数、外廓、内壁、承托面、开口、槽剖面和孔。
同名或不同目录的参考文件先比哈希；不要仅看文件名或旧表格认定来源不同。

- 内腔由实际内壁和空腔探针确定，不能拿槽边界、外廓或图像比例代替。
- 孔要检查完整拓扑和通路。圆柱面也可能是长圆孔的端部、外圆角或盲孔；记录孔中心与圆弧中心的区别。
- 原文件内与目标零件一起导出的层板、装配参考不能误作本车组件。
- 保留源 STEP。通过刚体变换建立局部零件坐标和装配坐标的明确关系。

## 让 MCP 操作对用户可见

用户正在参与造型时，优先启动桌面 SolidCraft 并连接其窗口：

```sh
solidcraft --control 27878
SOLIDCRAFT_CONNECT=127.0.0.1:27878 python3 cad_solidcraft/scripts/build_battery_cradle.py
```

这些是本机示例；先检查进程和端口，不盲目重复启动。模型生成命令会新建设计，运行前确认其作用范围。
`cad_solidcraft/scripts/sc_mcp.py` 提供同一连接内顺序调用的客户端。
没有会话内直接暴露的 SolidCraft 工具时，可以通过该客户端启动 CLI 的 MCP stdio 端点；如实说明使用方式。

- 连接后用 `inspect_design` 核实目标窗口和模型。不要覆盖用户未保存的工作。
- 保持一条 MCP 连接完成一轮相关操作；无窗口会话彼此独立，不会自动把已有模型搬到桌面。
- `--headless` 适合隔离验证、回放或批处理。使用时先说明用户看不到这个会话，不能声称“窗口已更新”。
- 命令参数以正在运行的版本返回的 `tools/list`、`describe_command` 为准。后者参数名是 `id`，不是 `command`。
- 每一步检查协议错误、`isError` 和时间线错误；不要只看子进程退出码。
- 改完用 `view.apply` 展示相关视角。保存模型后再做临时诊断视角，避免用户打开文件看到不完整检查状态。

## 把自然语言转成几何不变量

把约束写成可测关系，而不是复刻某版图形。

| 用户表达 | 应落实的约束 |
|---|---|
| 槽移到中间，不碰孔和柱 | 槽完整扫掠路径与固定件、螺母窝、功能边保持间隙；不能只查槽中心 |
| 扎带槽要贯通 | 检查底部通道、端壁窗口、外扩边和包绕路径；切除后不得留下薄桥 |
| 底板整体加厚，槽深不变 | 槽顶 = 新底面 + 槽深；不要锁定旧槽顶坐标而把槽自动加深 |
| 柱子被边覆盖 | 检查铜柱的实际接触轮廓及螺母窝剩余壁厚，而不只是孔中心落在板内 |
| 加边，要美观、有功能 | 统一边宽、端部过渡和左右关系；边用于承托、加强、保护或装拆，避免零散凸耳堆叠 |
| 电池空间保持 | 冻结内腔及承托面的要求，分别核对螺母、螺柱、线缆是否侵入 |

分开表达底板厚度、槽深、槽上剩余厚度：`剩余厚度 = 底板厚度 - 槽深`。
底板变化后重新检查端壁切除高度；“原来切透”不保证新模型仍切透。

## 五金决定安装结构

沿紧固轴列出尺寸链：柱身、外螺纹、铁板、夹持层、垫片、螺母、孔深和电池承托面。
例如 M3×10+4 通常表示 10 mm 柱身加 4 mm 外螺纹，但仍要说明朝向，核对实际规格。

- 外螺纹长度应覆盖夹持层和有效螺母啮合；螺柱末端不得进入电池空间。
- 普通 M3 螺母、薄螺母、自锁螺母高度不同，不能互换假定。
- 螺母窝要考虑扳手或落入路径、防转和打印间隙；标准尺寸与打印补偿分开记录。
- 支架、铜柱、螺母作为独立实体；打印导出只含支架。未建真实螺纹时标明是名义包络。
- 铜柱、沉入式螺母座、加厚底板都会改变电池承托高度，重新算上层净空。
- 实物配合和承载没有测过，不能由 CAD 相交检查宣称已经可靠。

## 选择稳定、可编辑的建模方式

先保住功能空间，再建立固定结构，最后检查通道是否被后续特征堵住。
优先原生特征、清晰的草图和有意义的表达式；不要为了参数化而给无关尺寸都加变量。

对导入 STEP 的局部改造可以直接建立编辑特征。若导入体布尔反复失败：

1. 判断实体、目标体、接触关系、重合面和切除范围；先做小而可观察的验证。
2. 不保留失败特征，不连续盲目重试，也不把失败隐藏为“已完成”。
3. 简单几何可以按源实体测量重建原生特征；复杂自由曲面不能凭外廓替代。
4. 重建后对**不允许变化的区域**做体积差或表面检查，证明内腔、开口等确实保留。

过渡造型服务于功能。圆锥、圆角失败时可选简单筋或整体加强边，但应重新检查打印、接触和通路，而非只追求布尔成功。

## 独立验收，不把一次成功当作交付

SolidCraft 用于设计，FreeCAD/OCCT 可用于独立读回检查。运行方式见仓库 README。
FreeCAD Python 先加载 `FreeCAD` 再加载 `Part`，使用安装包运行时及 `PATH_TO_FREECAD_LIBDIR`。

按改动选择必要检查：

- 单实体、有效、闭合；时间线无错误；参数改动后形状确实变化，恢复后与原状态一致。
- 内腔、开口、固定孔、螺母窝、夹持厚度和槽深。曲线 STEP 的普通包围盒可能偏大，可用 `optimalBoundingBox()` 核对，不能直接放宽公差。
- 对槽使用全长体积探针，分别检查空区、剩余材料和两端出口。
- 对保留区做参考几何差；对装配检查孔位、支撑面、五金干涉和工具进入空间。
- 源件只有曲面时，先用包络筛查，再检查表面交叠。壳的体积为零不代表没有碰撞。
- STEP 重新打开；STL 闭合；原生设计重新打开；以输出文件为对象验收。

分别报告**零件几何通过、五金匹配、整车装配状态、实物未验证项**。
发现 TOF 等其他组件干涉，保留证据并请求相应设计选择，不擅自移动设备，也不把总体报告改成通过。

## 收尾和经验沉淀

按仓库规则保存当前模型、生成脚本、检查报告和有用视图，更新 README 与当前设计说明。
移除被替代的生成结果和自动备份，保留仍适用的组件源文件；不自行提交或推送。
如果用户只要求写 skill，就提炼已经验证的方法，不把尚未解决的干涉包装成成功案例。
